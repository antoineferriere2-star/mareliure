## Nouveaux cas — P2, tous exécutés par PostgreSQL/PGlite

Les cinq cas ci-dessous donnent `undeclaredTables(sql) === []`, créent réellement une nouvelle table publique sans décision de droits et laissent `has_table_privilege('authenticated', cible, 'SELECT') = false`. Chaque essai est annulé par ROLLBACK. Une assertion verte caractérisant ces défauts ne signifie pas qu’ils sont corrigés.

| Cas | Reproduction | Cause relue / correctif proposé |
| --- | --- | --- |
| CTE suivi de SELECT INTO | `WITH payload AS (SELECT 1 AS id) SELECT * INTO public.build_notes FROM payload;` | La branche SELECT INTO n’est appelée que si l’instruction commence par SELECT. Couvrir WITH et distinguer le SELECT final. |
| Table temporaire puis persistante dans le même DO | `DO $$ BEGIN CREATE TEMP TABLE scratch(id int); CREATE TABLE public.build_notes(id int); END $$;` | Un seul motif TEMP TABLE exempte tout le corps dynamique. Exiger une décision explicite pour les créations persistantes du même corps. |
| Collision avec les jetons internes qidN | `CREATE TABLE public.qid0(id int); CREATE TABLE public."other_notes"(id int); GRANT SELECT ON public."other_notes" TO authenticated;` | Le vrai identifiant qid0 est interprété comme le jeton du nom cité. Utiliser des jetons structurés ou une représentation qui ne puisse pas être produite par un identifiant SQL ordinaire. |
| Point dans un identifiant cité | `CREATE SCHEMA "public.case"; CREATE TABLE public."case.notes"(id int); CREATE TABLE "public.case".notes(id int); GRANT SELECT ON "public.case".notes TO authenticated;` | Les clés schéma.nom fusionnent deux couples distincts. Utiliser un couple structuré et comparer le schéma exact, sans startsWith. |
| Échappement du mot CREATE dans une chaîne E | `DO $$ BEGIN EXECUTE E'\x43REATE TABLE public.build_notes(id int)'; END $$;` | La recherche dans les littéraux ne décode pas les échappements. Signaler un SQL dynamique non analysable, même si son texte ne contient pas CREATE en clair. |

Le marqueur `-- acl: dynamic-reviewed` est **volontaire** : un contrôle dédié vérifie qu’il accepte un corps relu, et que son retrait rétablit le signalement. Il n’est pas présenté comme un défaut. Les nouveaux contournements n’utilisent aucun marqueur d’exception.

Pour une garantie plus forte, compléter l’analyse statique par une répétition sur PostgreSQL avec inventaire des relations publiques avant/après et décision de droits explicite. Aucun correctif du détecteur n’est mélangé à cette contre-revue.
